# 운영 규칙서 (실수 방지 기준)

> 매일 자동 실행(예상글·매매·게시)이 따라야 하는 확정 규칙. 프롬프트(`prompts/kr-report.md`·`us-report.md`·`portfolio.md`)와
> 코드(`scripts/`)에 이미 반영되어 있으며, 이 문서는 **왜 그렇게 정했는지**와 **재발 방지 체크리스트**의 원본이다.

---

## 0. 역할 분리 — AI 6명 (2026-07-28 개편: 매니저 3인 → 5인)

한 회차에 **서로 다른 Claude 세션(=AI 6명)** 이 순서대로 일한다. 헤드리스 `claude -p`를 여섯 번 호출 → 세션이 분리되어 기억을 공유하지 않는다. **먼저 매니저 5명(①~⑤)이 각자 종목을 확정**하고, **마지막에 애널리스트(⑥)가 5인의 선택을 종합해 "오늘의 매수/매도 종목"을 정리**한다.

| 순서 | 담당 | 프롬프트 | effort | 하는 일 | 산출물 |
|---|---|---|---|---|---|
| ① | 🛡️ **안정형** 매니저 | `persona-stable.md` + `portfolio.md` | xhigh | 가치·방어 관점 매매 | `portfolio/orders/<날짜>-<세션>-stable.json` |
| ② | 🚀 **공격형** 매니저 | `persona-aggressive.md` + `portfolio.md` | xhigh | 성장·모멘텀 관점 매매 | `…-aggressive.json` |
| ③ | 🙂 **평범형 1** | `persona-normal1.md` + `portfolio.md` | xhigh | 성향 없음 — 데이터가 가리키는 대로 | `…-normal1.json` |
| ④ | 🙂 **평범형 2** | `persona-normal2.md` + `portfolio.md` | xhigh | 〃 (③과 **지시문 동일**) | `…-normal2.json` |
| ⑤ | 🙂 **평범형 3** | `persona-normal3.md` + `portfolio.md` | xhigh | 〃 (③과 **지시문 동일**) | `…-normal3.json` |
| ⑥ | 🧠 **애널리스트** | `<kr\|us>-report.md` | xhigh | **주문서 5개를 종합** → 종목별 매수/매도 결론 리포트 | `_posts/<날짜>-<kr\|us>-market.md` |

### 왜 이 구성인가 (2026-07-28 확정)
- **①② 성향파 = 극단 양 끝.** 서로 반대되는 색깔을 일부러 부여. 이 둘이 같은 종목을 사면 성향을 뛰어넘는 강한 신호다.
- **③④⑤ 평범형 = 대조군.** 셋의 프롬프트 파일은 성향 id 한 글자만 빼면 **글자까지 동일**하다. 목적은 성향 비교가 아니라 **"같은 데이터·같은 지시문에서 AI 판단이 얼마나 갈리는가"(편차) 측정**이다.
  - ⚠️ **의도적으로 다르게 만들지 말 것.** 셋을 차별화하는 순간 대조군으로서의 의미가 사라진다.
  - 세 계좌가 갈리는 실제 경로: ⑴ 샘플링 비결정성, ⑵ 세션마다 다른 웹검색 결과, ⑶ 도구 사용 순서, ⑷ **하루 지나면 보유·현금이 달라져** 이후 판단이 구조적으로 벌어짐.
  - 리포트에서 평범형 3인은 **독립된 3표가 아니라 같은 조건의 반복 시행**으로 다룬다("3명이나 샀다"로 표를 부풀리지 않는다). 셋이 수렴 = 데이터가 명확 / 셋이 분산 = 오늘 데이터가 애매.
- **2026-07-20~07-27 존재했던 🎯 역발상형(contrarian)은 2026-07-28 폐지**했다. 프롬프트·계좌·주문서·자산곡선·페이지 모두 삭제. (그 기간 발행된 `_posts/`의 서술은 발행 당시 기록이라 **그대로 보존**한다.)
- **시작일이 다르다**: ①② 2026-07-20 개시 / ③④⑤ 2026-07-28 개시(각 1억). 누적 수익률을 나란히 비교할 땐 `days`(N일차)를 함께 봐야 한다.

### 공통 규칙
- 5명은 **같은 `market.json`을 보되 각자 판단**(리포트는 아직 없음 — 각자 1차 결정) → 각자 독립 계좌 `_data/portfolio-<id>.json`.
- 애널리스트는 5인의 주문서(`orders/<날짜>-<세션>-*.json`)를 읽고 **두루뭉술한 시황이 아니라 "이 종목 사라/팔아라"** 를 종목 단위로 종합한다(편집 결론 — 실행은 안 함).
- 데이터 수집·차트·스크리너·체결계산은 **파이썬**(`scripts/portfolio.py <label> <persona>`, 5회)이 한다.
- **손익 비교 가격의 출처는 파이썬이 수집한 `data/<날짜>/market.json` 하나** — 다섯 계좌의 체결·평가가 모두 이 동일 파일 기준. 그래서 같은 잣대로 채점된다.
- 경계: 애널리스트는 주문/계좌를 안 건드린다. 매니저는 글(`_posts`)·남의 계좌를 안 건드리고 자기 주문서 하나만 만든다. 모두 git 금지(커밋은 워크플로).
- 비용: 회차당 세션 **6개 전원 xhigh** → 토큰 소모가 4개 시절 대비 1.5배. Max 리밋이 부담되면 매니저 effort를 `high`로 낮추거나 평범형 수를 줄이는 선택지(`daily.yml`).
- 페이지: `/portfolio/`=5인 비교 허브, `/portfolio/<id>/`=계좌별 상세(증권앱형).

## 1. 스케줄 (하루 2회 · **장이 열려 있는 동안** · 평일 KST)

> **2026-07-15 최종 확정 — 제1원칙: 리포트를 본 사람이 30분 안에 같은 가격대로 실제 매수할 수 있어야 한다.**
> 그게 안 되면 리포트가 무의미하다. 그래서 **장중에 발행**한다.
> AI의 임무는 단순하다 — **"지금 시장가로 사면 오를 종목"** 을 콜하는 것. "이미 반영됐나" 같은 논의는 하지 않는다(반영 여부와 무관하게 지금 가격에서 오를지만 본다).

| 분석 시작 (KST) | 모드 | **발행·체결** | 하는 일 |
|---|---|---|---|
| **14:30** | `kr` | **~14:45** | 🇰🇷 장중 — 수집+차트+스크리너 → 매매결정 5인 → 종합 리포트 → **AI가 본 시세로 체결** (독자는 15:30 마감 전 매수) |
| **23:30** | `us` | **~23:45** | 🇺🇸 장중 — 수집+차트 → 매매결정 5인 → 종합 리포트 → **AI가 본 시세로 체결** (독자는 장중 바로 매수) |

### 발행 시각을 고정하는 이유·방법 (중요)
- **독자가 "언제 보면 되는지" 알아야** 30분 내 매수가 성립한다. 그래서 발행 시각을 매일 고정한다.
- ⚠️ **GitHub 예약실행은 지연이 크다 — 실측 최대 2시간 20분**(크론 04:45 → 실제 07:02 시작). 정상 동작이며 제어 불가.
- 그래서 **크론을 목표보다 ~3.5h 일찍 걸고**(kr 11:00=`0 2`UTC / us 20:00=`0 11`UTC), 워크플로의 **"목표 시각까지 대기"** 스텝(epoch 계산·자정 안전)이 정확히 14:30 / 23:30에 시작시킨다 → 발행 매일 ~14:45 / ~23:45.
- ⚠️ **주의(2026-07-20 수정)**: 대기 로직을 문자열 비교로 짰다가, 지연으로 자정 넘겨 시작한 **US 런이 23시간 대기→취소**된 버그가 있었다. epoch 초 계산 + 6h 상한으로 수정. 크론도 목표 3.5h 전으로 당겨 지연이 있어도 목표 '전'에 시작되게 함.
- 파이프라인 실측 소요: **~28분 예상**(AI 6명 — 4명 시절 실측 ~20분). 공개 저장소는 Actions 분이 무료라 대기 비용 없음.
- 🇺🇸 23:30 시작은 **연중 안전**(여름 22:30 개장 · 겨울 23:30 개장) → 서머타임 조정 불필요.
- 검증 루프: 어제 리포트 시점에 추천한 종목이 **지금까지** 올랐나/내렸나 대조(O/△/X).

## 2. 글 포맷 — PPT 슬라이드 + 접이식 전체 글 (2026-07-15 확정)

> 리포트는 매니저 5인 뒤에 실행되어 주문을 종합한다. **결론만 한눈에 보이는 PPT 슬라이드 5장**이 본문이고, 자세한 근거는 접이식(`<details>`)으로 숨긴다 — "PPT랑 리포트 둘 다".

- front matter에 **`slides: true` 필수** → `post` 레이아웃이 전체폭 슬라이드 모드로 렌더(`_layouts/post.html` + `_includes/ppt-style.html`).
- 본문 = `<div class="ppt">` 슬라이드 5장 + `<details class="full-report">` 상세.
  1. **01 표지·결론** — `.cover`: 큰 제목 + `🔴 매수 (종목) / 🔵 회피 (종목)` (매수=빨강 `.call.buy`, 회피=파랑 `.call.sell`)
  2. **02 시장 한눈에** — `.grid`의 `.stat` 타일 4~6개(상승 `.up`▲빨강 / 하락 `.down`▼파랑)
  3. **03 5인의 선택** — `.three`의 `.who` 5칸(안정·공격·평범1~3 — 매수종목·현금%). `.three`는 폭에 맞춰 자동 배치(5열 또는 3+2)
  4. **04 종합 매수/매도** — `.verdict-list`의 `.vl.buy`/`.vl.sell` (종목 + 근거 + `.agree` 5인중 누구) — **핵심**
  5. **05 핵심 한 줄** — `.big .huge` 대립 두 단어 + 포트폴리오 링크
  - `<details class="full-report">` — 종목별 상세 근거 · 5인 상세 · 어제 채점(마크다운 서술)
- 슬라이드 CSS 소스: `_includes/ppt-style.html` (`slides: true` 글에 자동 적용).
- 색 규칙(한국식): **매수·강세=빨강**, **매도·약세=파랑**. 파일명 `_posts/YYYY-MM-DD-<kr|us>-market.md`.
- front matter 필수: `market: kr|us` (목록이 🇰🇷 한국장 / 🇺🇸 미국장 **두 갈래로 분리**됨) · `slides: true` · `date: YYYY-MM-DD HH:MM:00 +0900` — **HH:MM은 실제 작성 시각**(워크플로가 `[실행 안내]`로 넘겨줌). 목록·글 상단에 "작성 시각"으로 분까지 표시된다.

## 3. 가상 포트폴리오 체결 규칙 (1억 페이퍼 트레이딩)

**매매는 하루 단위** (실시간 아님). AI가 **장중에** 판단·발행하고 **그 시점 시장가로 체결**한다.

| 규칙 | 내용 | 이유 |
|---|---|---|
| 체결가 | **AI가 분석한 그 시세(`market.json` 현재가)로 즉시 체결.** 가격을 보고 판단했으니 그 가격에 산다 | 27만원 보고 샀는데 29만원에 체결되면 판단이 무의미 |
| 룩어헤드 | 지금 가격 보고 지금 사는 건 **정상 거래**다. 손익은 이 시점 **이후** 시세로 결정되고 AI는 그걸 못 본다 | 반칙은 '미래 가격'을 보는 것 |
| 발행 시각 | 반드시 **장중**, 매일 고정. 🇰🇷 14:45(마감 15:30 전) · 🇺🇸 23:45 | **제1원칙**: 리포트 본 사람이 30분 안에 매수 가능해야 함 |
| 세션별 거래 시장 | **`kr` 세션 = 한국 종목만 · `us` 세션 = 미국 주식·섹터ETF만** (암호화폐·원자재는 24시간이라 양쪽 다 가능). 어긋나면 주문 무시 | 그 시장이 닫혀 있으면 시세가 오래된 것이라 그 가격에 살 수 없다 |
| 판단 기준 | **"지금 사면 오를까"만** 본다. "이미 반영됐나"는 논하지 않음 | 반영 여부와 무관하게 지금 가격에서의 방향이 유일한 질문 |
| 평가 | 매 실행마다 스냅샷 확정 → 일별현황·자산곡선 | 같은 방식으로 공정 채점 |
| 주식·ETF | **정수 주수만** 체결(한국·미국 공통), 잔액은 현금 유지 | 64.3주 같은 비현실 방지 |
| 미국 자산 | **달러 가격으로 평단·현재가 표시** + 체결 시점 환율(원/달러) 기록 | 원화 환산만 보면 왜곡 |
| 암호화폐·원자재 | 24시간 자산 → 소수 단위 체결(단위: oz/BTC 등, "주" 아님) | 0.5 BTC·1.9 oz는 현실적 |
| 주문서 | `portfolio/orders/<날짜>-<kr|us>-<성향>.json` — buy는 krw(예산), sell은 qty 생략 시 전량 | 세션·성향별 1회 적용(`applied_orders`) |
| 원칙 | 몰빵 금지·분산·각 주문에 근거(reason)·확신 없으면 hold | 이벤트 직전(발표 전) 추가 베팅 금지 |
| 검증 | 모든 수치는 커밋된 `data/`·`orders/`·`_data/portfolio-<성향>.json`과 대조 가능 | 신뢰성 — "대충 가상" 금지 |
| 미반영 | 수수료·세금·슬리피지 없음 (명시할 것) | 단순화 범위를 정직하게 공개 |

포트폴리오 페이지에는 반드시: 수량·평균단가·현재가(해외는 원통화 병기)·평가액·비중·손익 + **종목 클릭 시 거래내역(lots)** + 현금 행 + 일간변동 + 📒매매일지 + 📅일별현황.

## 4. 데이터 함정 (겪었던 실수 — 재발 방지)

- **yfinance 한국 지수(^KS11/^KQ11)는 하루 지연될 수 있다.** 급락일에 지수만 이전 값에 멈춘 사례 있음 → 글에서 지수 수치를 쓰기 전 `data_date` 확인, 지연이면 **개별 대형주+뉴스로 대체**하고 그 사실을 글에 명시.
- 지수의 `chg_pct`가 **2일 누적**으로 잡힐 수 있다(전일 데이터 지연 시) → 오늘 변동은 어제 종가와 직접 비교.
- **pykrx는 KRX 로그인 요구로 사용 불가** → 한국 유니버스는 FinanceDataReader.
- 스크리너(FDR)는 해외 서버에서 간헐 실패 가능 → 워크플로에서 `continue-on-error`, 실패 시 해당 섹션 생략.
- 클라우드(리눅스) 차트 한글: `fonts-nanum` 설치 필요 (폰트 자동 선택 로직 있음).
- Actions는 실행마다 새 환경 → **data/는 커밋**해야 다음 세션이 참조 가능 (스냅샷 `market-<kr|us>.json`).

## 6. 글쓰기 원칙

- 근거 없는 단정 금지 — 모든 판단에 데이터/뉴스 근거, 출처 병기.
- 확률로 말한다. 목적은 **적중이 아니라 기록·자기검증** (매 글에 어제 예상 채점 O/△/X + 교훈).
- 데이터 이상(지연·결측)을 발견하면 **숨기지 말고 글에 명시**한다.
- 스크리너 후보는 **뉴스로 재료가 확인된 종목만** 게재, 나머지는 제외 사실을 밝힌다.
- 모든 글 최상단에 "투자 조언 아님" 경고.
